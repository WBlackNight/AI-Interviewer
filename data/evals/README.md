# 检索smoke集

2026-10-28新增candidate_answer_cases.jsonl：六道候选各有完整、部分、错误回答，question_sha256绑定题目版本，expected_hits为项目作者参考。运行evals/review_candidate_answers.py对照离线规则评分；12/18集合一致、4例多判、2例漏判的本轮结果是诊断，不是独立质量分数或激活建议。参考标签、三类完整性或题目版本不匹配会拒绝执行；报告不输出回答正文。详情见[本轮日志](../../docs/开发日志-2026-10-28-题库候选与发布链路.md)。

`retrieval_smoke.jsonl`为开发者根据当前11题示例题库编写的10条合成查询，固定`split=smoke`。

2026-10-23题库扩展至Java/Python共18题；这10条原始查询仍只覆盖Java，保留原标注用于岗位过滤回归，不用于Python质量结论。新题库摘要和结果见`docs/logs/2026-10-23/retrieval-multi-position.json`。
每条包含query_id、query、统一filters及relevance（0不相关，1补充相关，3直接相关）。

这些是可审阅的开发者标注，不是多人独立盲评、真实面试分布或独立测试集。没有训练/调参划分，
也不应用于选择模型后再汇报“测试效果”。用于检查BM25、离线哈希/智谱向量、RRF是否在同一题库/过滤下
产出可复算的Recall@k、nDCG@k、MRR@k和实际耗时；每题候选数量写入报告。

BM25与向量均仅使用题目主题和题干，不额外使用参考答案。编码题默认被过滤；主题/难度未指定时
不限制相应字段。岗位、题型、已问题始终不放宽；默认仅在指定难度没有未问候选时放宽难度。

后续真实评测应补独立人工标注、开发/测试隔离、更大题库与查询分布、多个模型和误召回样本，
之后才能判断语义模型或混合检索是否带来质量提升。
