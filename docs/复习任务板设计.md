# 复习任务板与任务专项设计、验收

日期：2026-10-24。状态：复习清单、任务专项、自定日期、日期筛选及个人复习笔记已实现并本地验收；后续计划见末节。

## 用户流程

在所属已完成面试报告点击“加入复习任务”，把当前报告最弱主题保存到账户。顶部“复习任务”进入任务板，查看待复习/已复习/全部任务，按岗位筛选，手动标记已复习或恢复待复习；卡片可返回原报告。匿名报告需先登录并逐场认领，保留原匿名练习入口。

卡片可直接“练习本主题”，使用任务主题与原报告的岗位/强度，最多2道主问题并保留追问。存在未结束练习时显示继续入口；结束或取消后可再练。专项报告与导出保留任务/原报告来源，练习完成不自动改变手动状态。不同场次题目可能重复。

这是一份用户主动保存的复习清单。手动完成只记录学习安排，不修改面试分数、不推断能力提升，也不自动将后续练习作为完成凭据。个人笔记通过原生`/notes`页面编辑；没有自动排期、提醒或任务级删除，删除来源面试或账户时同步删除对应任务与笔记。

## 生成规则与数据

1. 仅所属finished面试可生成。created/running/cancelled返回409，无评分或无薄弱主题返回422；未登录401，非所属来源403。
2. 直接复用`build_report`的`weak_points`：同一主问题各轮平均，主题内主问题等权，严格低于`WEAK_SCORE`，取最弱2主题。客户端不决定主题、分数或状态。
3. 从该主题各轮评分的`key_points_missed`按评分顺序提取，去空/去重，最多8项，每项最多300字符。无要点时保持空数组，由页面提示查原报告；不调用模型补写。
4. `revision_task`保存id、account_id、interview_id、position、theme、加入时的source_score/weak_score、focus_points、status、created_at/completed_at。不额外保存回答、题干、简历或访问凭据。
5. 账户/来源/主题有唯一约束。写入先锁账户行，与原账户/来源删除流程保持串行化；同源已有任务直接返回，保留完成状态、时间和加入时分数。来源配置变化不会覆写已存任务。不同来源的同一主题是独立任务，便于返回各自的评分证据。
6. 完成状态todo/done。重复设置同值幂等；todo→done记UTC完成时间，done→todo清空完成时间。只修改任务，不触及评分、来源档案和能力画像。
7. 删除来源或账户时，在同一删除事务内先清任务，再清评分和源记录。任务列表/更新仅本账户可用，过期/退出会话沿用原授权拒绝。

## 接口

全部使用账户`Authorization: Bearer`，响应不缓存。

| 方法与路径 | 请求 | 响应/边界 |
|---|---|---|
| POST `/api/account/interviews/{id}/revision-tasks` | 无需请求体 | items、added、existing；不采纳客户端分数、主题或完成状态 |
| GET `/api/account/revision-tasks` | 可选status=todo/done、position；due=all/today/overdue/upcoming/unscheduled；offset≥0、limit=1–50，默认20 | 原列表字段，加due、date_counts、today、timezone；任务增加due_date |
| PATCH `/api/account/revision-tasks/{id}` | status=todo/done与due_date可独立提交或一起提交，至少一项；due_date为YYYY-MM-DD或null | 更新后的任务；他人或不存在任务404；额外字段/空对象/无效日期/显式status=null返回422 |
| POST `/api/account/revision-tasks/{id}/practice` | 无需请求体，不采纳客户端替代主题/岗位/状态 | 创建面试字段+revision_task_id/reused；复用未结束的同任务专项；未知/他人任务404，过期401，主题/岗位当前不可用422 |
| GET `/api/account/revision-tasks/{id}/note` | 无 | content、version、updated_at；无笔记返回空文本/0/null；他人或未知404，会话失效401 |
| PUT `/api/account/revision-tasks/{id}/note` | 必填content字符串、expected_version非负整数 | 成功返回笔记；版本不匹配409；超长、错误类型或额外字段422，不回显笔记正文 |

列表按created_at与id稳定倒序。counts统计当前岗位的全部待复习/已复习任务，不受状态过滤影响；positions仅来自本账户任务。前端每页20项，状态/岗位切换回到第一页，末页因状态修改消失时回到有效页。刷新恢复默认待复习/全部岗位，持久化的是任务进度。

## 任务专项一致性与生命周期

先锁当前账户行，再检查任务/原报告归属及完整完成状态。已有created/running专项时复用同一场，返回reused=true，不重新加载题库生成大纲；原场若因资产变化不能恢复，按已有取消入口结束后再创建。新建使用当前题库的岗位、知识主题和可用题数校验；不接受编码主题，不放宽为综合面试。

新增revision_practice表：递增主键、task_id外键、唯一interview_id外键。新面试/运行快照/账户归属和关联单事务提交，关联失败全部回滚；复用当前账户行写锁串行化同任务创建，避免重复点击/并发重试产生多场未结束练习。此行为已在本地SQLite真实HTTP并发验证，不代表多worker容量验收。

任务响应增加latest_practice（无关联时null），包含最新关联练习的id/status。报告增加revision_source（无关联时null），包含task_id、原报告interview_id和theme；Markdown同步导出这些来源字段。来源仅从服务端关联读取，未复制原回答、题干、简历或评分。新练习归当前账户，没有匿名凭据；todo/done及完成时间不因创建/继续/评分/练习完成变化。

删除原报告→先清任务所关联的所有revision_practice，再清任务/原报告；已创建专项独立保留，报告revision_source变null。删除专项→清该场关联和面试内容，原任务保留，latest_practice按剩余关联重算。删除账户→按原进行中保护规则清理全部所属场次、关联和任务。开启SQLite外键的回归覆盖这些顺序，不保留已删除源ID的额外副本。

## 验收与升级

### 自定复习日期（2026-10-24）

日历统一为北京时间（Asia/Shanghai，当前实现固定UTC+08:00）。due_date是日历日期，保存与显示均不转为UTC时间戳；只接收规范YYYY-MM-DD，范围2000-01-01至2100-12-31，允许过去日期，拒绝时间戳、日期时间、周日期、无效日和布尔值。列表一次计算today并返回，浏览器按服务端today判断徽标；跨日后点击刷新更新。

新增revision_schedule表：task_id为任务外键及主键，due_date为有索引的DATE。未安排时无关联行，响应due_date=null；清空日期删除该行。旧任务不自动排期，启动create_all只补新表，无既有列迁移。列表批量关联读取日期，重复加入原报告保持原安排。状态与日期只修改明确提交的字段，合法组合在同一事务提交；非法组合整体拒绝。沿用账户行写锁与授权，同字段按最后成功写入为准。

默认all保持创建时间/ID倒序。today是日期等于今日，overdue早于今日，upcoming晚于今日，unscheduled未指定日期；前三种按日期升序、创建时间/ID倒序稳定分页。日期筛选仅比较日历日期，可与todo/done组合查看原定安排；done卡片显示“原定复习日”，不显示“已逾期”。恢复todo保留日期，并按当前日期重新显示待办徽标。

counts仍统计当前岗位的todo/done，不受状态或日期筛选影响；date_counts统计当前岗位与所选状态下的四种日期数量，不受当前due视图和分页影响。positions仍包含本账户所有任务岗位。日期/岗位/状态切换回第一页，改期导致最后一页消失时退回有效页；全部筛选保留至本页刷新或离开。卡片通过日期输入、保存和清空显式修改，无自动保存。

完成/恢复、开始/继续专项不修改复习日期；改期/清空不修改状态、完成时间或评分。删除来源/账户时同事务先清日期行，再按原顺序清关联和任务；删除独立专项不清源任务日期。无自动提醒、对外发送或记忆推断。

### 个人复习笔记（2026-10-24）

新增revision_note表：task_id为主键及任务外键，content纯文本、version递增整数、updated_at为UTC保存时间。由create_all补齐缺失表，不修改已有列；旧任务默认空笔记。任务列表、状态/日期更新和重复加入响应增加note对象，列表按当前页批量读取，无逐任务查询。原Next页面忽略新增字段，现有构建可继续运行。

content最多2,000个Unicode码点，空字符串表示清空；CRLF/CR统一为LF后校验，保留其余空白与缩进，不解析Markdown或HTML。expected_version严格整数，不接受布尔/字符串。写入先锁当前账户并核实任务归属，再比较版本；同内容同版本不改时间/版本，不同版本即使内容相同仍拒绝。首次保存非空为1，修改或清空加1；清空保留版本行，防止旧草稿覆盖新状态。

原生页面`revision-notes.html`、`assets/revision-notes.js`复用home.css，通过`/notes`访问；首页主导航及页脚提供入口。每页10项，支持状态/岗位/日期组合筛选、分页和空末页回退。显式保存、撤销草稿、字符计数、过长禁止提交；冲突不自动重试，读取最新内容更新比较基线但不替换编辑框，支持手动合并或明确采用最新版本。页内刷新/筛选/翻页/开始专项先用原生dialog保护草稿；离开页面用beforeunload提醒，不在localStorage或后台保存草稿。创建专项失败保留草稿，成功跳转不重复提示已确认的放弃操作。

卡片可开始/继续现有主题专项；主题、岗位和来源仍由服务端任务决定，笔记不作为请求参数。日期和状态通过原任务板管理；保存笔记不改它们、评分或完成时间。笔记不进入题目规划、追问、评分、运行快照、能力画像或报告导出。删除来源/账户同事务先删笔记，再删关联和任务；删除独立专项保留源任务笔记。清空不提供历史版本恢复，版本用于并发校验，不是历史档案。

新增16项后端测试；全量后端545项加网关16项共561项通过。真实HTTP两场合成报告验证同版本并发200/409、重启、独立登录、幂等、清空后拒绝旧版本及删除。浏览器完成纯文本保存、刷新/独立登录读取、跨会话冲突与合并、草稿保留及390/1440视口；专项入口确认复用同一场。见[笔记日志](开发日志-2026-10-24-复习笔记.md)。

## 原生工作区与后续推进

### 原生任务板与复习搜索（2026-10-24）

原生`/revision`由revision.html、revision-board.js与home.css组成，承接原任务板的完成/恢复、安排/清空日期、来源报告和主题专项。首页/笔记/任务板共用导航风格，不引入新框架、依赖或Next构建；本机`/legacy-revision`保留原Next任务页。账户、记录和报告继续使用现有构建，后续再统一。

GET列表新增q及note_filter：q最多100个Unicode码点，去首尾空白后为空则不筛选；主题或已保存笔记包含字面子串即匹配，ASCII英文忽略大小写；SQL参数绑定并转义LIKE通配符，百分号、下划线、斜线和引号不扩大查询范围。note_filter为all/with/without，有笔记指content非空字符串，保留的空白同样算内容；无关联或已清空均算无笔记。只在本账户任务范围查询，不访问他人笔记或未保存草稿，不作模型或语义检索。

搜索与笔记条件在岗位条件之后、状态与日期之前应用。counts统计这些条件内的全部todo/done，date_counts继续限定所选状态、独立于due及分页。positions仍来自本账户全部任务。响应增加规范化query和note_filter，其余字段及排序不变；旧调用默认all且q为空，保留原查询行为。

原生任务板每页8项、笔记页10项，筛选提交回第一页，末页因更新消失时回到有效页；刷新回默认待复习。搜索只检查已保存内容，编辑后显式保存即可参与下一次查询。卡片展示来源分与未覆盖要点、笔记摘要；写入分别只提交日期或状态。保存成功重新读取统计，读取失败保留原卡片并提示。日期草稿在切换、翻页、其他任务写入与专项跳转前由dialog保护，默认保留；离页仍有浏览器提醒。搜索词不写入页面地址或客户端存储，API GET参数会包含关键词，日志按账户内容脱敏边界管理。
