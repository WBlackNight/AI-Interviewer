# 数据库版本与运维

数据库升级现在统一由app/schema_versions.py登记，启动时在同一数据库锁与事务内建表、升级、登记版本。SQLite使用BEGIN IMMEDIATE，PostgreSQL使用事务级advisory lock；后者仍需在实际PostgreSQL环境验收。

现有两项旧库修复依次登记为001_interview_nullable和002_event_sequences，保留原迁移函数的独立调用兼容性。重复启动不重复执行已登记升级；未知的更高版本会拒绝启动，避免旧代码修改新库。新版本必须追加迁移函数和版本号，不能仅修改模型后依赖create_all改变现有列。

003_goals_and_shares新增preparation_goal与report_share两张表。阶段目标与原准备计划关联，分享只保存令牌散列和用户选择范围的报告快照。移除计划会清理其目标，删除面试或账户会清理对应分享。部署此版本前按下文备份实际数据库并执行upgrade。

004_account_details新增account_details表，保存选填性别、年龄、简介及资料版本。旧账户默认未填写，新资料仅通过账户授权接口读写；删除账户时一并清理。原昵称、头像和邮箱继续使用现有账户资料表。

005_assistant新增assistant_conversation表，保存账户所属的助手对话、版本及临时生成租约。旧账户无需补填数据；删除账户时清理对应对话。升级应先备份，历史对话不属于练习资料导出的恢复范围。

从backend/执行：

```powershell
.\.venv\Scripts\python.exe -m app.manage_database status
.\.venv\Scripts\python.exe -m app.manage_database upgrade
```

升级前停止旧实例并用tools/backup_database.py备份实际数据库，核对完整性和保存位置。upgrade不会自动生成备份。已有数据的升级应先在副本上运行，并核对账户、练习和报告。启动锁用于防止同时升级，不替代滚动发布的版本兼容设计。

迁移失败时数据库事务回滚，版本登记也不会提交。已成功迁移的回退采用“恢复旧代码和升级前数据库备份”，不提供可能丢失新数据的自动降级命令。恢复前需要停止所有连接、保存当前数据库副本，并在新的文件路径验证备份可读；不能直接用旧备份覆盖正在运行的库。

本机预览默认临时数据；需要保留时显式选择--persist，使用backend/preview-data.sqlite3。直接运行后端使用配置的DATABASE_URL，两者不同。账户页“下载复习数据”只导出个人复习资料，不能用于完整恢复。

账户安全页可查看本人有效会话数量，验证当前密码后退出其他会话。此操作保留当前会话、撤销该账户其他令牌，不影响其他账户。
