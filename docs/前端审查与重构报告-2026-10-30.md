# 前端审查与重构报告

日期：2026-10-30，北京时间。范围：当前16页原生前端、公共样式、本机页面网关、前端验证与交付链路。目标仍为“准备→练习/对话→保存→报告→复习”，沿用FastAPI契约与30题资产，不重写后端或改用新框架。

## 审查结论与处理

| 优先级 | 发现与影响 | 本批处理 |
| --- | --- | --- |
| 高 | 多页重复读取sessionStorage，但校验账户ID、用户名和到期条件不同；维护一处容易遗漏其他页 | 统一readSession，账户、令牌和文本DOM模块按需注入16页脚本 |
| 高 | 账户、历史、任务、笔记等JSON请求没有完整覆盖“正文读取期间账户变化”；部分页只在解析前核对 | guardedFetch在JSON读取完成后复核捕获的会话，拒绝旧响应；保留调用方取消/超时/写入不重试策略 |
| 高 | 交付脚本普遍逼近15,000字节，直接追加逻辑缺少统一失败门禁 | 源代码与产物分离，生成器先准备并检查全部文件，CI拒绝过大或过时产物；容量约束本身仍保留 |
| 中 | 117,073字节共享CSS混合旧视觉与多轮覆盖，前一轮曾出现四组内容被五列样式覆盖 | 拆为8个有序维护模块；移除48条被覆盖声明及72组不可达旧选择器，维持级联顺序与居中布局 |
| 中 | 工作区每页导航不同，计划、题单、笔记入口不易发现，没有当前页标识 | 12个工作区页采用同一导航，aria-current标记当前页；桌面紧凑、窄屏容器内横向滚动；练习/报告/语音保留场景内导航 |
| 中 | 网关、资源白名单、页面集合和导航独立维护，新增页面易漏同步 | ui/manifest.json统一登记，生成器和网关读取同一份清单；保留精确匹配、别名308、合法ID与未知路径404 |
| 中 | 多个业务页面禁用JS时只剩静态骨架 | 模板提供noscript恢复提示；既有语义表单、原生dialog/details、键盘操作和焦点样式保留 |
| 中 | README和接入说明不断累积旧版本、旧题数、旧验收数据，阅读入口失真 | 当前README改为简洁维护指南，完整历史归档，最新进度与专题报告可追溯 |
| 中 | CI没有检查源代码/交付一致性，也遗漏语音脚本和公共层竞态回归 | tools/verify_ui.py成为统一入口，覆盖16脚本语法、结构约束、公共模块、12项答题恢复协议及两套语音状态检查 |

本次没有发现需要以引入框架或重写业务状态机解决的问题。重复提交、旧轮次恢复、草稿冲突和语音设备清理已有明确协议，因此保留其行为边界，避免结构重构改变保存语义。

## 新结构

```text
ui/manifest.json       页面/导航/脚本/样式顺序
ui/templates/          16份页面模板
ui/pages/              16份页面业务源码
ui/shared/             session / token / element / fetch
ui/styles/             8份按序合并的样式
tools/build_ui.py      标准库生成器及--check
tools/verify_ui.py     本地与CI共用检查
根目录HTML + assets/   生成后的可交付产物
```

源代码可读，产物保留函数和语句换行，只精简整行注释及缩进，不混淆变量名。每页仍只请求HTML、一个CSS、一个JS，工作区34文件不增加运行时模块依赖。本机网关仍是开发设施，静态ZIP不是生产后端部署方案。

## 验证与证据

证据目录：logs/2026-10-30/frontend-refactor/。

- gateway-tests.xml：31项网关回归通过，覆盖规范地址、mode、查询参数、授权头与资源/路径边界。
- verification.json：统一入口通过生成一致性、16脚本语法、结构/字节约束、公共模块、12项答题恢复协议和两套语音状态检查。
- layout.json：16页分别在1440、390、320宽度下巡检，共48次，无横向溢出、可见文字小于14px或可见alert错误。使用带计划/笔记/历史的隔离账户，包含有数据的报告及两种语音模式。
- flow.json：浏览器账户登录、笔记显式保存后刷新可见、创建Python/Web专项、短句回答5.2分、只针对遗漏的连接关闭追问、刷新恢复1轮、两次跳过结束3轮并进入报告。浏览器控制台无错误。
- dashboard-desktop.jpg、dashboard-mobile.jpg：统一工作区视觉证据；before-source.zip保留重构前34文件及网关。
- delivery-check.json：两个静态包及前端源代码包逐成员一致性和当前凭据扫描。

本批不重跑未改动的全部后端用例，历史739/156项不计入本批测试总数。未申请麦克风、未调用真实模型、未改.env或开发数据库；本机Chromium结果不能代替Safari/真机、语音音质、语义评分质量或生产容量验收。

## 后续改进方向

1. 生产工程：统一HTTP/WS反代、缓存版本策略、部署回滚和真实监测；当前本机网关不能作为生产代理。
2. 性能：共享CSS仍覆盖16页，应在明确调整“三静态资源/15KB”约束时评估按页裁剪与缓存；不要为满足单个指标引入更多隐式请求。
3. 产品质量：人工标注评分/追问、扩大岗位题库、验证当前题的真实语音表现；结构测试不等于回答质量。
4. 体验：真机键盘、屏幕阅读器、Safari录音与回声测试；当前仅验证本机Chromium与离线设备边界。
5. 技术栈：frontend/的旧Next兼容入口独立存在，依赖升级和退役应单独进行；本批没有将旧构建伪称为原生重构成果，也未验证其发布构建。

这些是尚未完成的独立验收方向，不影响当前原生前端结构重构的交付。
