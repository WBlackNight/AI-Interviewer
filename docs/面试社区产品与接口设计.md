# 青栈面试社区产品与实现

## 产品方案

面试社区服务于模拟练习前后的交流。欢迎用户分享面试经历、回顾一个答题难点，或向其他练习者请教。

| 场景 | 交互 | 权限与反馈 |
| --- | --- | --- |
| 找讨论 | 首页显示帖子流，支持综合、最新；全部、精华、我的帖子、我的收藏 | 公开内容可匿名浏览，个人筛选需登录，空结果可回到全部 |
| 选择身份 | 登录后可在边栏选择身份，首次发帖或回帖也会就地引导 | 学生、公司职员为自选标签。选择前说明用户名、昵称、头像将公开显示 |
| 发帖、回复 | 填写标题、正文，或在帖子详情写回复。可插入内置表情 | 后端写入当前身份快照，提交失败保留输入，成功反馈并进入详情或回复区 |
| 点赞、收藏 | 帖子详情点击一次添加，再点击取消 | 按钮显示实际状态及点赞数。收藏内容仅本人可见，公开主页展示收藏总数 |
| 搜索 | 输入用户名、昵称、标题或身份关键字，分别展示用户和帖子 | 两组独立分页。命中文字高亮，空结果分别说明 |
| 举报 | 帖子或单条回复可打开举报窗，选原因及补充说明 | 反馈已提交或已经举报。举报人信息和说明不在社区公开显示 |
| 审核 | 管理员从管理工作台打开举报队列，检查正文后填写决定 | 支持待审核、已驳回和已下架，保存审核人、时间与说明。观察员没有权限 |

身份在用户主页显示当前值。帖子与回复显示发布时值，后续改身份只影响新内容。自选身份用于理解分享语境。

回复采用平铺、按时间正序、分页的结构。一条回复对应一个稳定身份快照与举报目标。平铺减少手机端缩进和横向拥挤，也便于逐条审核。以后如果有大量讨论分支，可以增加单层引用字段，仍按时间阅读。

精华阈值默认 **10 个有效点赞**，通过 `FORUM_FEATURED_LIKES` 配置。点赞回落到阈值以下后，精华标签同步取消。综合排序分数为 `3×点赞 + 2×可见回复 + 8×精华 + 时间加权`。最近 24 小时加 12，近 7 天加 5，其余加 0，同分按发布时间和 ID 降序。最新排序只按时间与 ID 排。

## 数据库

沿用 SQLite 和 SQLAlchemy，由 `007_forum` 迁移登记。ID 是 32 位十六进制字符串，日期时间在数据库以 UTC 语义保存，接口输出 UTC 时间。下表中的 PK 为主键，FK 为外键。

| 表 | 字段与类型 | 键、索引与用途 |
| --- | --- | --- |
| `account` | `id VARCHAR(32)`、`username VARCHAR(32)`、`password_hash VARCHAR(256)`、`created_at DATETIME` | 已有用户表，id PK，username 唯一索引 |
| `account_profile` | `account_id VARCHAR(32)`、`nickname VARCHAR(32)`、`email VARCHAR(254)`、`avatar BLOB`、`avatar_version VARCHAR(32)` | 已有资料表，account_id 同时为 PK 与 account FK，email 唯一。论坛只投影昵称和头像 |
| `forum_profile` | `account_id VARCHAR(32)`、`identity VARCHAR(24)`、`updated_at DATETIME` | account_id PK/FK，identity 索引。存在一条记录即已开启公开社区主页 |
| `forum_identity_change` | `id VARCHAR(32)`、`account_id VARCHAR(32)`、`identity VARCHAR(24)`、`created_at DATETIME` | id PK、account_id FK，组合索引 (account_id, created_at)，记录实际发生的身份变化 |
| `forum_post` | `id VARCHAR(32)`、`author_id VARCHAR(32)`、`identity VARCHAR(24)`、`title VARCHAR(100)`、`body TEXT`、`status VARCHAR(16)`、`created_at DATETIME` | id PK、author_id FK；组合索引 (status, created_at, id)、(author_id, created_at)，另有 identity 索引。status 为 published/hidden，精华按点赞数实时派生 |
| `forum_comment` | `id VARCHAR(32)`、`post_id VARCHAR(32)`、`author_id VARCHAR(32)`、`identity VARCHAR(24)`、`body TEXT`、`status VARCHAR(16)`、`created_at DATETIME` | id PK，post_id/author_id FK，(post_id, status, created_at, id) 和 author_id 索引。正文限 1500 字符 |
| `forum_like` | `account_id VARCHAR(32)`、`post_id VARCHAR(32)`、`created_at DATETIME` | (account_id, post_id) 复合 PK，两个字段分别 FK 到账号和帖子。post_id 索引支撑点赞统计 |
| `forum_bookmark` | `account_id VARCHAR(32)`、`post_id VARCHAR(32)`、`created_at DATETIME` | (account_id, post_id) 复合 PK，两个字段分别 FK 到账号和帖子。post_id 索引 |
| `forum_report` | `id VARCHAR(32)`、`reporter_id VARCHAR(32)`、`post_id VARCHAR(32)`、`comment_id VARCHAR(32) NULL`、`target_kind VARCHAR(8)`、`target_id VARCHAR(32)`、`reason VARCHAR(20)`、`note VARCHAR(300)`、`status VARCHAR(16)`、`created_at DATETIME`、`reviewer_id VARCHAR(32) NULL`、`reviewed_at DATETIME NULL`、`review_note VARCHAR(300)` | id PK；reporter_id/reviewer_id 指向 account，post_id/comment_id 分别指向帖子和回复。(reporter_id, target_kind, target_id) 唯一。(reporter_id, created_at)、(status, created_at, id) 用于配额与审核队列。post_id、comment_id、reviewer_id 各有索引 |

精华由实时关系计数派生，无冗余字段需要补偿同步。下架是软状态，公开列表、详情和搜索只展示可见内容。执行账户删除时，事务内清关联帖子、回复、互动及身份记录。其他举报记录中的已删除审核人引用置空，保留决定和时间。

## API

以下路径的统一前缀为 `/api/forum`。标记了可选登录的公开接口，如果发来有效会话，会返回本人的点赞或收藏状态。登录使用现有 Bearer 会话。通用分页接受 `offset=0..10000`、`limit=1..30`，响应为 `{items, next_offset}`。下表中的路径 ID 由服务端校验格式和存在性。

| 方法与路径 | 参数 | 成功响应 | 权限 |
| --- | --- | --- | --- |
| GET `/context` | 无 | `{identities, report_reasons, featured_likes, viewer}`，viewer 为 null 或 `{id,identity,can_moderate}` | 公开 |
| PUT `/identity` | JSON `{identity: student\|employee}` | `{identity,updated_at}` | 登录，本人 |
| POST `/posts` | JSON `{title,body}`，标题 1–100，正文 1–8000 字符 | 201 `{id}` | 登录并已选社区身份 |
| GET `/posts` | `sort=rank\|latest`、`filter=all\|featured\|mine\|saved`、分页 | 帖子摘要分页 | 公开，mine/saved 需登录 |
| GET `/posts/{post_id}` | 路径 ID | 帖子详情，包括正文和本人反应状态 | 公开 |
| GET `/posts/{post_id}/comments` | 路径 ID、分页 | 回复分页，包括作者、正文、历史身份、发布时间 | 公开 |
| POST `/posts/{post_id}/comments` | JSON `{body}`，1–1500 字符 | 201 `{id}` | 登录并已选社区身份 |
| PUT 或 DELETE `/posts/{post_id}/like` | 路径 ID | `{liked,saved,likes,featured}` | 登录，本人操作 |
| PUT 或 DELETE `/posts/{post_id}/bookmark` | 路径 ID | 同上 | 登录，本人操作 |
| POST `/posts/{post_id}/reports` | JSON `{reason,note?}`，说明最多 300 字符 | `{id,status,duplicate}` | 登录 |
| POST `/posts/{post_id}/comments/{comment_id}/reports` | 同上，需为此帖下的回复 | 同上 | 登录 |
| GET `/search` | `q` 1–64 字符，`post_offset`、`user_offset`、`limit` | `{query,posts:{items,next_offset},users:{items,next_offset}}` | 公开 |
| GET `/users/{user_id}` | 路径 ID | `{id,username,nickname,avatar_url,identity,post_count,saved_count,recent_posts,is_self}` | 已开通的社区主页公开 |
| GET `/users/{user_id}/posts` | 路径 ID、分页 | 该用户帖子摘要分页 | 公开 |
| GET `/users/{user_id}/avatar` | 路径 ID | PNG | 已开通的社区主页公开 |
| GET `/moderation/reports` | `status=pending\|dismissed\|actioned`、分页 | 举报摘要分页，含对象、原因、时间和审核摘要 | 管理员 |
| GET `/moderation/reports/{report_id}` | 路径 ID | `{id,body,content_status}` | 管理员 |
| PATCH `/moderation/reports/{report_id}` | JSON `{decision: dismiss\|hide,note}`，说明必填、最多 300 字符 | `{id,status}` | 管理员，已审核返回 409 |

帖子摘要含 `id,title,excerpt,author,identity,created_at,likes,comments,featured,liked,saved`。单帖用 body 替换 excerpt。作者投影为 `{id,username,nickname,avatar_url}`。举报原因代码为 spam / abuse / sexual / politics / copyright / other，对应广告、辱骂、色情、政治敏感、侵权和其他。

## 前端结构

论坛通过 FastAPI 注册的 `/forum` 提供页面，并加入全站导航。列表按卡片显示标题、正文片段、作者、身份与互动指标。电脑端为讨论区加「我的社区」侧栏，手机端堆叠为单列。页面使用原生组件和青栈现有样式。小青和管理工作台继续使用 React 与 TypeScript。

| 页面 | 地址及内容 |
| --- | --- |
| 论坛首页和列表 | `/forum?filter=…&sort=…`，从标题和标签进入相关讨论，展示筛选、排序和分页 |
| 帖子详情 | `/forum?post=ID`，正文、身份快照、点赞收藏、举报、回复流和输入框 |
| 发帖 | `/forum?view=new`，登录与身份门槛、标题正文、内置表情、字符数 |
| 搜索结果 | `/forum?q=…`，用户和帖子两组结果与独立分页 |
| 用户主页 | `/forum?user=ID`，头像昵称、当前身份、公开计数和最近帖子，本人可编辑资料、改身份、查看收藏 |
| 审核队列 | `/forum?view=moderation`，按状态筛选、查完整被举报内容、记录处理决定 |

内置表情使用 Unicode，插入文本选区后更新计数。展示时写入文本节点，搜索高亮是通过 `mark` 包裹文字，不解析用户提供的 HTML。以后如本模块迁移至 React，可按 `ForumFeed`、`PostCard`、`Composer`、`EmojiPicker`、`ReportDialog`、`Profile` 和 `ModerationQueue` 拆分。

## 安全与搜索扩展

- SQLAlchemy 参数化查询。搜索使用转义后的不区分英文字母大小写的字面子串匹配。百分号和下划线按字面处理。现阶段提供子串匹配，拼写纠错与语义召回需检索索引支持。
- 发帖和回复做长度、非空、控制字符、配置词表和链接数量检查。词表初始仅覆盖少量典型广告词，实际内容治理由自选词表和管理员审核共同承担。
- 点赞、收藏为幂等 PUT/DELETE，复合主键是最后一道防重约束。一个账户对一个目标只保留一条举报，每 24 小时最多 5 次有效新举报记录。审核状态变更条件为 pending，并与下架在同一事务内提交。
- 身份选择前明确提示公开字段。账户邮箱、密码散列、答题资料、收藏列表和个人资料详情隔离在原账户权限内。
- 小青访客看到登录提示。完整页和浮窗使用同一组件，匿名调用对话接口返回 401，登录后回到原页面。

当前 SQLite 查询需扫描部分候选，精华和综合分也随互动重新计算。容量增长时，先用真实数据测搜索和综合列表的 P95。可先用 SQLite FTS5 或数据库全文索引处理全文匹配。中文短词要单独评估分词、同义词与召回。需要独立扩缩容、拼写容错和多字段权重时，再引入 Elasticsearch，由数据库作为权威数据源，同步发布与下架状态，并定期校对索引删除。参考 [SQLite FTS5](https://www.sqlite.org/fts5.html) 和 [Elasticsearch 全文查询](https://www.elastic.co/docs/reference/query-languages/query-dsl/full-text-queries)。

## 部署验收

和上一版使用同一 Compose 项目和数据库卷。上线前按部署指南备份数据库，保留服务器现有环境文件，重新构建。应用启动注册迁移 007。论坛审核菜单只对 `ADMIN_ACCOUNT_IDS` 中的账户开放。首次上线时论坛从真实用户首帖开始，演示数据仅在本机隔离预览。

本地回归通过前端 60 项、后端 79 项和静态页面检查 38 组。浏览器在桌面及 390px、320px 视口走查登录回跳、身份修改、带表情发布、点赞、收藏、回复、搜索高亮和举报下架。移动视口使用浏览器模拟。云端环境尚未部署本版本。
