# 数据可靠性与会话管理重构

本批继续审视现有账户、数据库启动和前端管理流程。确认前批最终后端837项全部通过；本批没有覆盖用户已有的demo-profile及演讲文档。

## 实施结果

1. 新增schema_versions统一迁移入口。SQLite使用BEGIN IMMEDIATE锁住建表、升级与版本登记；PostgreSQL使用事务级advisory lock。迁移失败整笔回滚；已有版本不重复执行，未知新版本拒绝降级。旧迁移函数保留独立调用兼容。SQLite连接等待锁上限调整为30秒。
2. 新增python -m app.manage_database status/upgrade。status不会创建不存在的SQLite文件，upgrade由统一入口执行。备份与恢复步骤写入数据库运维文档，升级命令不自动覆盖数据库或执行降级。
3. 账户安全API返回本人有效会话数量；验证当前密码后可撤销其他会话，保留当前令牌和其他账户。密码失败时不撤销会话，密码只在显式提交时发送，处理后清空输入。
4. 账户页新增会话管理卡片、数量与状态反馈，密码支持显隐，窄屏单列；延续个人空间、资料设置、复习导出和安全操作的既有结构。

## 实际边界

测试使用隔离SQLite，PostgreSQL分支和生产滚动升级未实测。本轮未调用真实邮件、模型或语音服务；没有把静态检查当作浏览器视觉或真机验收。多实例统一限流、忘记密码/更换邮箱和真实投递仍有独立工作，不宣称生产级全面验收。新增迁移版本只登记现有两项升级；以后修改已有列必须显式追加版本函数。
