## 选型与范围

正式交互入口采用React18＋严格TypeScript＋Vite8，FastAPI继续提供同源HTTP、SSE和WebSocket，SQLite沿用版本化升级与账户访问控制。当前主要是登录后交互与实时练习，选择推荐中的React＋Vite能保留已验收API和资源地址，开发时具备热更新，部署时仍只需一个后端服务。参见[Vite开发说明](https://vite.dev/guide/)及[后端集成方式](https://vite.dev/guide/backend-integration.html)。

本轮完成两个正式页面：`/assistant`小青与`/interview/{id}`文字练习室。其余页面仍使用现有原生实现；语音和实时对话模式保持既有路由。Next历史页面留在frontend/app，通过独立legacy命令维护，不作为正式页面重复入口。Next兼容依赖锁升级到15.5.29；本轮正式验收对象为Vite构建，不声称完成Next全站迁移。

样式继续复用青栈CSS变量与独立页面样式，控制按钮、卡片、输入框和反馈的一致性。既有Tailwind保留给兼容页面；没有为了展示技术名称加入不必要的UI库、3D或模型SDK。AI工具调用在服务端执行，前端只消费受约束协议，密钥不进入构建。

## 开发与构建

首次在frontend执行`npm ci`。Node需20.19+或22.12+，本机为24。`npm run dev`打开127.0.0.1:5173，后端默认127.0.0.1:8000；可在frontend/.env或终端设置QINGZHAN_DEV_PORT调整后端端口，代理目标始终限制为本机。开发入口为/assistant，练习入口仍为/interview/{id}，语音/实时模式代理回原实现；不同端口的标签页凭据各自独立，完整流程验收优先使用后端同源预览。

正式构建顺序：

```text
cd frontend
npm run build
npm test
cd ..
python tools/project.py build
python tools/project.py check
python tools/project.py serve --port 3000
```

`npm start`会选用backend/.venv中的Python启动同一服务；可用PORT环境变量调整端口。`build:assistant`与旧tools/build_assistant.cjs作为兼容命令同时构建两个React入口。每页190KB脚本预算包含React生产运行时；两个页面只加载各自入口，不让首页引入React。修改共享源码后两个入口均需重建。Python构建校验所有当前React源文件与构建配置指纹，防止发布旧产物。

## 数据与恢复

题目由服务端question事件提供，用户answer_ack只写入回答历史，不会作为追问题干。收到保存确认才清理待提交内容；同轮同版本的未确认提交可使用原message_id重放，已提交快照会清除重发资格。轮次或版本变化时保留旧回答到独立恢复区，禁止移到新题。账户凭据变化即关闭连接并清空当前可见数据。取消保留已保存回答，通过部分报告回看。没有新增数据库列或迁移版本。

## AI核对与评测边界

`assistant_grounding.py`仅在检索命中联合索引指南时检查三类已知错误。模型仍以真实增量展示；命中规则后发出revision事件替换临时文本，前端明确说明原因，后端只保存替换后的指引。中断或异常结束仍不保存半截回答。否定和不确定表达有回归样例，但规则存在漏检可能，不能替代专业审校。

`data/evals/assistant_grounding.jsonl`包含12条人工编写回归输入，覆盖错误表达和正常解释；`python evals/assistant_quality.py`不联网，输出逐例结果。它验证回归规则，不衡量所有知识回答的准确率，也不能据此证明RAG相比无检索显著提升。

最终实屏证据与测试日志保存在docs/logs/2026-11-16/migration；该目录不进入普通源码分发。验收使用独立离线数据库和合成回答，评分反映本机启发式链路，不代表真实模型评分或求职能力结论。
