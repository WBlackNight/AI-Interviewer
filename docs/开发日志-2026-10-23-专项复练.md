# 开发日志：主题专项与薄弱项复练

日期：2026-10-23（Asia/Shanghai）。依据[进度评估](进度评估-2026-10-23.md)和[技术实现步骤](技术实现步骤.md)，接续[双岗位交付](开发日志-2026-10-23-双岗位.md)。

## 交付与接口

- 首页新增“综合面试/主题专项”。专项可选择岗位当前有知识题的1至`MAX_PLAN_THEMES`个根主题（默认最多3个）；切换岗位清空选择，专项不上传或解析简历。
- `GET /api/positions`新增`practice_themes`和`practice_theme_limit`。编码专属主题不进入候选，原`roots`和岗位字段保持兼容。
- `POST /api/interview`新增可选`themes`。省略/null为原综合面试；提供空列表、重复、跨岗位、无题或编码主题返回422。同时带resume_id返回422。专项不调用LLM规划，主题等权，每主题最多2道主问题，无编码题；保留原难度及同主题难度放宽、追问和同场排除。
- 完整报告的`practice_themes`列出当前可复练的薄弱知识主题。它取现有`weak_points`（低于`WEAK_SCORE`的至多2个最低分主题）与当前可用根知识主题的交集，不重新放宽至其他主题；部分报告为空。
- `POST /api/interview/{id}/practice`使用来源`X-Interview-Token`，无需请求体。服务端读取完整报告，保留原岗位/强度创建新面试与独立凭据；无效/他场凭据403、未完成409、无可用薄弱知识主题422。报告页仅在存在可复练主题时显示按钮，创建中锁定，失败可重试。
- 新场不复制来源用户关联、简历、回答、评分。沿用既有plan、运行快照、数据库事务和授权表，没有新增列或修改题库/索引；无需列迁移或重编码Embedding。重启服务后使用新页面。
- 新增`evals/practice_smoke.py`并接入CI配置。脚本启动隔离服务、使用hash混合检索和规则评分、清理本次临时数据库及进程，不调用外部模型。
