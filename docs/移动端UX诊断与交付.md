# 青栈移动端 UX 诊断与交付

本次基于 2026-11-18 云端更新源码包。已核验附件 SHA-256 和文件清单，在独立副本完成修改。主要用户路径是手机打开首页、配置练习、回答、查看报告。测量使用本地 Chromium 响应式视口，结果用于前后对照。

## 1. 问题诊断

| 类别 | 原版表现 | 对用户的影响 |
| --- | --- | --- |
| 视觉层级 | 首页先放营销文案、演示框和数字，再展示轮播、流程、评分及问答。390px 宽度下，练习表单顶部约在 8,362px | 首屏出现多个视觉中心，用户想开始练习时要靠锚点跨越大量内容 |
| 导航结构 | 顶部四个并列入口加「更多功能」和账户区，窄屏压缩文字并换行。同页底部和桌宠又重复提供部分入口 | 要区分岗位页、题库、练习和复盘的位置，手机上还容易被浮层遮挡 |
| 触控适配 | 在紧凑视口中，二级链接、筛选和辅助按钮的大小、断行规律不一致 | 单手点按时目标不稳，连续填写或切换模式时容易误触 |
| 新手引导 | 方向、难度、综合与专项、时长和简历连续出现。文字和语音页面又使用大段介绍，有些辅助操作始终占位置 | 首次练习要先理解一组术语，语音服务关闭时还可能把「题目已同步」误读为可以录音 |
| 性能 | 账号轮播在手机上也有周期计时，下方示例与首页登录态预览可能同时初始化 | 阅读时内容变化，浏览器需要为下方尚未浏览的长内容做额外布局与绘制。现场缺少移动网络和设备数据，暂未量化加载耗时 |

## 2. 优先级排序

| 优先级 | 本次改动 | 收益 | 成本 |
| --- | --- | --- | --- |
| P0 | 首页先露出练习配置，普通入口默认标准难度和 5 分钟 | 缩短从打开首页到第一题的路径 | 低 |
| P0 | 手机一行页头，菜单按练习、记录与复盘、准备、账户帮助分组 | 降低导航密度，保留完整入口 | 低 |
| P0 | 精简答题标题与语音状态，统一常用控件的触控尺寸 | 更快看见第一题和主要操作 | 低至中 |
| P1 | 收起题库和记录的细分筛选，调整账户、角色与报告标题 | 用户进入页面后立即知道它能做什么 | 低 |
| P1 | 手机轮播手动切换，推迟视口外示例渲染与首页初次预览请求 | 减少阅读干扰和非必要首屏工作 | 低 |

P0 和 P1 已随本包交付。真实设备和网络体验属于部署后的评估项。

## 3. 具体修改方案

- **首屏。** 页头之后是「练一场模拟面试」、一句说明和开始按钮。390px 下，实际配置表单顶部约 373px，提交按钮底部约 753px。方向、预计用时是主要字段，强度和主题在「更多练习设置」，简历单列为可选项。「看示例」可直达原有互动演示。
- **导航。** 手机页头保留品牌、菜单、账户三处。菜单用原生可展开控件，按任务分组，支持 Escape 关闭。小青在手机菜单中进入，桌面仍可通过桌宠打开。语音和实时对话保留练习场内的模式入口。
- **控件。** 手机常用按钮与菜单项瞄准 44px 触控高度，开始按钮至少 48px，表单输入、选择器与文本域为 16px。主要内容左右留 16px，控件间距采用 8–12px，常用卡片内距 16px。320px 作为检验宽度。参考 [W3C 触控目标规范](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)和 [W3C 重排规范](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。
- **第一次练习。** 默认建议 5 分钟，说明标准难度与答题模式。用户可展开专项、调整难度、改用自动安排或添加简历。已有模式与主题链接会自动展开相关设置。语音权限说明就近展示，实时对话在开始前收起空白回答区。
- **反馈与帮助。** 保留页面内校验、加载和重试状态。专项缺主题时展开设置并把焦点移到错误提示。空记录提供开始练习入口，指南可从首页配置区及菜单找到。语音未启用时独立展示原因，文字作答仍可切换。

## 4. 可执行变更清单

| 改什么 | 为什么 | 交付结果 |
| --- | --- | --- |
| 首页首屏和练习表单 | 减少首屏竞争和配置选择 | 700px 及以下把同一个表单移到介绍下方，主流程先见方向、时长和提交按钮 |
| 全站移动导航与账户按钮 | 避免压缩和遮挡 | 单行布局、分组菜单、清晰的账户文字，保留品牌返回首页 |
| 桌宠 | 移动浮动入口会叠加在页面操作区 | 在手机宽度收起浮层，保留菜单入口与桌面桌宠 |
| 题库和记录 | 一上来铺开筛选影响阅读 | 题库直接显示关键词，细分筛选展开。记录保留状态按钮，岗位和强度折叠 |
| 账户和岗位页 | 产品文案占用表单和岗位列表的首屏空间 | 手机收起账户宣传区和岗位流程卡，登录、注册与岗位入口更靠前 |
| 文字、语音、实时练习 | 区分连接状态、练习方式与下一步动作 | 文字页优先提问与输入，异常时提供重同步。语音流程图折叠为就近提示，实时对话开始前仅在状态允许时展示对应操作 |
| 报告和助手 | 便于先阅读内容，再考虑其他入口 | 直接命名练习报告与表现改进，手机助手减少欢迎区装饰，保留对话和建议 |
| 低频展示和动画 | 控制信息变化与首屏绘制量 | 手机手动翻看账号轮播，未登录或未读取完账户数据时不显示三项零统计，下方长示例按需绘制 |

保留 React 18、TypeScript、Vite、原有页面模板与 CSS 变量、FastAPI 和同源 API/WSS。传智杯推荐的 React + Vite 路线已经在现有项目使用。本轮采用原生可展开控件和 CSS 响应式层，依赖锁文件沿用云端基线。

本机验收覆盖 320px 和 390px 手机视口及 1280px 桌面。手机流程依次检查配置校验、匿名练习、保存回答、语音关闭时切回文字、完成报告、题库空结果和登录入口。桌面验证导航和首屏示例切换。60 项前端测试、47 项相关后端测试及 37 组页面检查通过。

## 5. 后续验收还需要什么

- 用户集中反馈的具体页面与任务，例如「首页选完岗位」「打开实时对话」「看不懂复盘」，附一段操作路径有助于定位。
- 常见机型、系统、浏览器及字号设置，优先补 iOS Safari、Android Chrome 和常用内置浏览器。
- 可访问的云端预览地址及测试账号的安全访问方式，用于实际验证登录后工作区、移动浏览器麦克风权限和实时通话。
- 如需量化性能或转化，提供首题到达率、开始练习耗时等已有匿名数据，或约定采样口径。

部署使用包内的 `compose.cloud.yml`。已有部署请先备份，保留原来的 `deploy/cloud/.env` 和 `deploy/cloud/app.env`，沿用相同 Compose 项目名和数据卷，从新源码目录执行构建更新。附带的部署文档记录完整操作。
