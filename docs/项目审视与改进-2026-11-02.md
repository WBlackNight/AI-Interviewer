# 项目审视与改进（2026-11-02）

## 当前架构与优先问题

本页前半为初次审视记录；后续实施状态见文末，不能把已完成项继续当作缺失项。

- 当前原生前端由ui/生成，Next工程为兼容入口；同时维护两套入口会提高部署和回归成本。应逐步明确唯一生产入口，保留兼容路由直至迁移完成。
- 预览脚本使用临时SQLite数据库，退出后不能把演示数据视为持久数据。开发库与预览库需明确区分；生产环境需要持久存储、定期备份及恢复演练。
- 数据库启动依赖create_all和专用升级函数，尚不是完整的版本化迁移体系。生产升级前应引入迁移版本、备份、回滚和旧库升级验收。
- 账户登录限流使用进程内锁和计数，多进程或多实例不能共享限额；生产部署需共享限流状态，并验证反向代理下客户端地址可信性。
- 邮箱目前支持初次绑定与改密验证；更换邮箱、找回密码、真实SMTP投递和恢复流程仍需完整设计与验收。
- 实时语音已通过合成音频的历史联调；设备授权、真人麦克风、网络变化和跨浏览器体验仍需实机验收。
- 账户页面已有练习概览和数据删除入口，但数据导出、保留期限及备份状态缺少统一的用户体验。

## 本次已实施

新增tools/backup_database.py，使用SQLite在线备份API生成独立副本并进行integrity_check，拒绝覆盖目标，失败清理未完成文件。维护文档说明备份与恢复边界，账户页补充数据管理说明。生成了更新后的账户页面。

备份不替代恢复演练，也不支持PostgreSQL；预览临时库需先确认正确源路径。测试：SQLite备份/失败清理与账户回归24项通过；前端统一检查26项通过。尚未进行全量后端回归、浏览器视觉验收或生产备份恢复演练。

续批新增账户复习数据JSON导出，包含当前账户的复习任务、笔记、日期、题单标记和准备计划；每类最多1000条，超过上限明确拒绝，报告继续使用原有单场导出。导出不包含登录凭据，也不包含简历、完整练习答案或头像，不能当作完整数据库备份或直接恢复文件。账户页新增下载入口与状态提示，并调整数据管理区域样式。账户脚本预算调整为28KB。

后续新增同源原生入口：后端直接提供已构建页面与静态资源，API和WebSocket使用同一地址；原Next兼容和临时预览入口保留。页面路由限制在manifest与面试/报告路径内，旧.html页面重定向保留查询参数。WebSocket支持显式允许的来源或严格同源，恶意来源继续拒绝。同源入口已通过真实本机HTTP及WebSocket冒烟；公网HTTPS、代理和多实例部署尚未验收。

预览增加--persist，使用独立的backend/preview-data.sqlite3并在停止后保留；此模式不注入演示账户，也不允许演示种子参数。原临时模式不变。持久预览仅适用于本机，不等于生产数据管理方案。

## 本次继续重构

数据库启动改为版本化升级入口：建表、旧库修复与schema_migration版本登记共享数据库锁和事务；支持幂等、失败回滚、拒绝旧代码降级操作新版本数据库。SQLite并发启动、旧数据保留、失败回滚已验证；PostgreSQL锁分支尚未实测。维护命令与恢复流程见[数据库版本与运维](数据库版本与运维.md)。

账户安全页新增有效会话数量、验证密码后退出其他会话，当前标签页保留登录。旧令牌即时失效，不影响其他账户。新的会话管理卡片沿用主题颜色与控件，在窄屏改为单列；保留密码显隐与处理状态。

首次完整重构的最终测试结果已确认：837项通过。本次迁移/会话变更的最终结果记录于docs/logs/2026-11-02/refactor-v2/，不与前批测试数量相加。浏览器工具此前因无法确认URL而中断，本轮没有把静态/状态回归当作视觉验收。邮箱找回与更换已在后续功能批实现，见头像裁剪与邮箱恢复日志；真实SMTP、真人麦克风及多实例共享限流仍需部署实现与验收。
