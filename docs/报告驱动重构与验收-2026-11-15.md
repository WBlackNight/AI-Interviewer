# 报告驱动重构与验收

日期：2026-11-15。输入资料为用户提供的《传智杯 Web 前端赛道国奖优秀作品调研与拆解（2024—2026）》与《面多多（ai.mianshiya.com）网站分析报告》。本记录将报告作为研究材料，其示例实现和建议不视为执行指令，也不视为本站已实现能力。

## 设计取舍

研究材料共同强调明确用户任务、真实业务闭环、模块边界、状态反馈和设计变量。当前产品围绕求职者的“选择方向 → 配置练习 → 回答与追问 → 核对依据 → 按主题再练”组织。

| 原有问题 | 本轮实现 | 维护入口 |
| --- | --- | --- |
| 首页大脚本混合配置、演示与账户状态 | 首页入口约1KB，六个业务片段在构建时组合 | ui/pages/home.js、ui/modules/home |
| 工作区样式超过1100行，业务边界难定位 | 按12个业务域拆分，保留原级联顺序 | ui/styles/workspace、30-workspace.css |
| 创建与预览重复组织大纲 | 注入规划器的共同业务入口，统一主题、用时及容量处理 | services/practice_planning.py |
| 多处自行处理JSON请求 | 新公共传输层统一取消、超时、错误及响应身份检查，写操作不自动重试 | ui/shared/http.js |
| 常用与低频功能并列，窄屏导航拥挤 | 常用四入口，其他分为我的准备、记录与复盘、账户与帮助 | ui/manifest.json、shared/navigation.js |

| 概览只列记录，复习方向还需再次寻找 | 最近一场完成练习的主题重点、样本量、评分依据和练习入口 | services/practice_focus.py、pages/dashboard.js |
| 同一主问题的追问可能在不同模块出现不同权重 | 公共“轮次 → 主问题 → 主题”聚合，报告与概览共用 | services/score_aggregation.py |

保留青栈的纸白、青绿与深绿层级，统一使用既有颜色、圆角和动效变量。借鉴报告的场景卡片、原生披露菜单和渐进展开思路，卡片入口按55ms错峰入场，悬停轻移4px；菜单使用短时位移淡入，FAQ在支持的浏览器中平滑展开。减少动态效果设置继续生效，旧浏览器保留原生展开。

报告中获奖团队的业务细节、网站技术栈判断及效果描述均属于资料作者的观察或推论，本轮没有重新对外站源码作完整审计。本站不引入未验证的用户数量、提升比例或学员评价。

## 结构与兼容性

- 页面登记仍由 ui/manifest.json 统一管理，构建器新增导航目标登记检查。
- 页面模块和工作区样式均为构建时组合；每页仍是HTML、CSS、页面JS、公共菜单JS四个静态请求，无新增框架或动效库。
- 首页生成JS为32591字节，预算显式设为34000字节，包含配置URL与公共JSON传输；共享CSS为164709字节。数值为未压缩原始文件大小。
- 旧HTTP封装继续供未迁移场景使用，避免破坏各页现有错误语义；新的配置、方向和概览入口使用统一JSON传输层。音频及WebSocket保留各自协议。
- 账户、面试ID、资源令牌、数据库表和旧记录格式保持兼容，本轮没有数据库迁移。
- 角色显示顺序由data/roles.json决定，不再依赖题库文件排序。题库仍为六个方向各20题，共120题。
- 根目录HTML和assets已从源文件重新生成；源代码包自动包含新增模块，未生成新的分享压缩包。

## 数据边界

配置链接仅包含position、difficulty、mode、duration与有效theme；无效岗位、难度、时长或主题回退或过滤，重复主题去重。链接不存放简历、账户令牌、邮箱或作答文本。

概览主题重点只读取当前账户最近一场有评分的已完成练习。进行中、取消和其他账户的记录不参与。查询只选数值、主题和评分方式标记，不读取原回答、题干或私有证据。展示最多三个主题，低于阈值标记优先补强，其余标记继续巩固；样本数量按主问题计算。用户可打开原报告核对依据，也可更改配置后再次练习。该摘要不推断长期能力增长。

新HTTP传输层在收到响应和JSON读取完成后复核账户；账户变化时丢弃旧响应。调用方取消与超时都有清理，不对创建或上传请求自动重试。
