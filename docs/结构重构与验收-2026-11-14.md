# 结构重构与验收记录

本次从岗位配置、出题容量、评测反馈和账户交互整理原生应用。指定参考站为 https://ai.mianshiya.com/ ，浏览器访问返回安全拦截，网页抓取超时。未核实其实际动效、颜色、用户管理后台或出题算法，本次实现依据当前项目的问题与已有功能设计。

## 维护边界

| 内容 | 入口 |
| --- | --- |
| 岗位名称、分组与能力重点 | data/roles.json |
| 时长与题量策略、公开岗位数据 | backend/app/practice_policy.py |
| 实际题量与主题容量 | backend/app/services/practice.py |
| 练习预览接口 | backend/app/api/practice_config.py |
| 逐题诊断与补强建议 | backend/app/services/assessment.py |
| 账户资料请求校验 | backend/app/api/account_inputs.py |
| 认证限流依赖 | backend/app/api/dependencies.py |
| 练习方向页面 | ui/templates/roles.html、ui/pages/roles.js |
| 开始前的大纲预览 | ui/shared/practicepreview.js |
| 统一设计变量 | ui/styles/00-tokens-base.css |

构建器与服务端共享标准库实现的岗位规则。首页的岗位选项、题量、常见问题文案和 JavaScript 目录从题库生成。新增方向时维护岗位元数据、题库与技能树，再构建前端。

时长配置为 5/10/15 分钟，最多安排 2/3/4 道知识主问题。分配先覆盖主题，再参考权重补充题量，并受实际题库容量约束。追问另计。自动安排保留原有编程环节，知识题量同样受容量约束。

新会话在同岗位、主题和难度的检索候选中按会话种子选题。种子随快照保存，重连恢复仍使用相同策略。旧快照缺少种子时沿用原排序。逐题固定复练继续直接锁定原题。

报告按独立主问题聚合后，从已有得分、已覆盖要点和遗漏要点生成能力表现与优先建议。反馈不额外调用模型。阶段报告会标明当前只包含已提交的回答。

账户头像菜单集中展示账户中心、资料、安全与指南。未登录时提供登录注册入口。注册、资料、邮箱和密码校验集中在各自请求模型，三个账户路由共享同一认证限流依赖。

静态资源地址由构建器追加内容摘要版本号。CSS、页面脚本和账户菜单任一内容变化时，引用它的 HTML 自动更新资源地址，避免用户继续读到旧缓存。前端检查逐项核对地址中的版本号与文件字节是否一致。

## 验收

已通过 143 项后端回归，覆盖练习时长、预览与实际专项题量、选题变化、快照恢复、注册登录、邮箱、安全会话、资料修改、固定复练和评分完整性。浏览器在隔离空数据库中完成 Java 后端 5 分钟练习，提交一轮合成回答并跳过另一题，结束后成功查看报告中的表现和补强建议。窄屏检查包含练习方向页、报告和账户菜单。方向分类、主题搜索、菜单键盘关闭和资源更新后的实际加载均已在浏览器验证。

本次浏览器验收使用本机离线服务。真实麦克风通话、远程模型语义质量、生产数据库及公网部署需在对应服务环境验证。
