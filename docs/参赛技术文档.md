## 01 项目概述与需求分析

### 使用场景

备考者常能找到大量题目，却很难判断一次作答漏掉了什么，也难以安排下一轮练习。青栈把方向选择、模拟面试、评分依据和后续任务放在一条路径上。用户可先体验一场短练习，有持续准备需求时再登录归档。

| 用户任务 | 产品设计 | 验收条件 |
| --- | --- | --- |
| 第一次开始 | 首页推荐短时练习，先选岗位和时长，简历可选 | 浏览题库或直接创建练习，避免强制登录 |
| 针对薄弱主题补练 | 题库按岗位和主题筛选，支持主题专项 | 创建、恢复和再次练习保留主题约束 |
| 看懂反馈 | 报告提供逐轮回答、评分依据和待补充点 | 能从报告定位原回答，也能开始主题复练 |
| 练习口头表达 | 文字、语音作答和独立实时对话入口 | 音频权限与能力不可用时提供文字入口 |
| 持续准备 | 账户记录、计划、任务、题单、笔记；社区同伴交流 | 个人数据按账号隔离，公开分享经显式授权 |

### 数据规模与边界

运行题库共 120 道主问题，Java 后端、Python 后端、市场营销、运营管理、教育教学与英语面试各 20 道。题库和技能树是版本化的本地数据，分开保留候选语料与运行集合。报告用于自我练习和复盘。

### 使用流程

选择方向与时长 → 预览范围 → 作答与追问 → 查看报告依据 → 新建专项练习或复习任务。

## 03 数据模型与访问控制

| 数据域 | 主要记录 | 持久化策略 |
| --- | --- | --- |
| 面试 | 面试、运行状态、轮次事件、答题提交、评分、资源归属 | 以会话为边界保存答题版本和确认记录。断线后按快照恢复 |
| 账号 | 账号、会话、资料、头像、验证码挑战、资源归属 | 密码及会话令牌在库内以散列保存。过期、退出和删除流程各有约束 |
| 准备与分享 | 计划、复习任务、笔记、题单、报告分享 | 按账户和资源授权查询。分享范围、过期与撤销由服务端校验 |
| 小青 | 对话、回合消息、版本及幂等标识 | 完整回合才保存。会话只在对应账户下读取和修改 |
| 社区与后台 | 身份和历史、帖子、回复、点赞、收藏、举报、审校及审计记录 | 点赞和收藏使用唯一约束。身份以发布时快照展示。审核与下架同步提交 |

### 迁移与回滚

应用启动时运行版本化迁移，包括 005 助手、006 运营审校和 007 社区。SQLite 使用数据库级写锁串行迁移，事务成功后才登记版本。升级前使用备份工具生成一致性副本，保留 Compose 持久卷。发现数据库版本高于当前程序时停止启动，避免误降级。

### 访问控制

账户功能使用 Bearer 会话。匿名练习和简历使用作用域独立的凭据。管理者和只读观察员通过服务端账号 ID 配置。报告分享仅返回授权范围，社区的公开主页只投影公开字段。敏感接口响应禁用缓存，实时连接另校验来源。

## 04 AI 技术方案 · 规划、评分与追问

<!-- diagram:workflow -->

### 技术选型与集成

题库与技能树负责岗位、主题和评分锚点，规则可检查且能离线执行。文本模型接入 OpenAI 兼容接口，适合为现有业务做简历结构化、拟定大纲、评分表达和追问措辞。线上模型由服务端配置，所有流程均经过业务约束。

1. 规划。配置校验后从对应岗位和可用主题生成练习大纲，题量受时间档位和题库覆盖约束。预览与正式创建共享规划入口。
2. 评分。结合题目与锚点输出技术深度、表达逻辑、岗位匹配、已命中和待补充内容。结构化响应经校验。报告按轮次、主问题、主题逐层聚合。
3. 追问。系统先根据未覆盖锚点在技能树确定目标，再请模型改写问题。服务端核对节点、问题格式和候选回答重复情况。非法输出回退到安全提问模板。
4. 复盘。保留评分方式、样本与逐题证据。主题复练从报告提取受约束的范围，产生新的练习记录。

### 执行可靠性

回答保存使用消息标识及轮次版本校验。断线后先同步快照再决定是否重发，避免重复评分或将回答误当追问。模型调用提供可配置超时、有限重试、并发约束和预算。离线评分与模型评分使用不同来源标记。

## 05 AI 技术方案 · 小青与检索增强

### 为什么使用检索增强

小青的任务是准备面试。受控岗位题库和学习指南可以提供具体参考，也便于用户跳到可执行的练习入口。基础实现使用 BM25，中文词项、岗位元数据和主题过滤可在本地复现。需要向量时可显式启用离线哈希索引或远程嵌入，混合检索使用 RRF 合并排序。

| 阶段 | 已实现行为 | 质量控制 |
| --- | --- | --- |
| 规划工具 | 通过模型 Function Calling 选择受限的只读工具 | 白名单、参数校验、每回合限制。工具不能修改账户或直接启动练习 |
| 检索依据 | 按岗位从题库取最多三道相关题，结合该方向学习指南 | 在界面单独显示参考和站内行动入口 |
| 个性化 | 经用户选择后读取本账户最近练习的主题与评分摘要 | 练习原回答不进入这一步的摘要 |
| 流式生成 | SSE 传输阶段、内容增量、引用与最终状态 | 输出受边界检查。可停止接收，重放标识防重复写入 |
| 异常回退 | 首段失败或未配置模型时使用本地学习指引 | 标明来源。途中断流不会保存成已完成回合 |

### 优化与评估边界

只读工具、有限上下文和岗位检索减少无关输入。索引缺失或不匹配会按实现降级。文档中的测试验证约束、流式协议和典型知识边界。哈希向量仅用作离线基线。专家事实评测、真实场景盲测和无检索对照放入后续评估。

## 06 AI 技术方案 · 多模态与安全

### 文本、简历与语音

- 文字作答经 WebSocket 传输，练习室呈现当前问题、保存状态和上一轮反馈。
- PDF 简历先做文件大小、页数、文本长度和解析时限校验，再在隔离解析进程提取文本。有界文本用于规划与必要的主题调整。默认上限 5 MiB、10 页。
- 正式语音作答接收录音或受支持的 WAV，转写结果进入正式评分。实时语音陪练使用独立链路展示两侧对话、结束建议与优缺点。
- 网页只向同源应用发送音频和业务请求，服务端负责供应商鉴权和会话生命周期。公网麦克风体验使用 HTTPS 与 WSS，文本和语音凭据分开。

### 模型与内容控制

| 风险 | 当前控制 |
| --- | --- |
| 错误追问或越权工具调用 | 固定结构、状态校验、只读工具白名单和模板回退 |
| 输出被页面当代码执行 | 对话和社区文本按文本渲染。行动链接由应用生成并限定为本站已知路由 |
| 请求资源越权 | 账户、面试、简历和分享各有授权边界。管理员独立校验 |
| 过度调用与断流 | 预算、超时、并发、限流和断连清理。供应商已发生用量依其账单 |
| 公开环境泄漏 | 真实密钥只读取服务器环境。公网反代隐藏内部诊断和接口文档 |

文本脱敏为基础规则。隐私测试使用合成简历、回答和账号。生产部署应继续限制个人资料采集与供应商输入范围。

## 08 技术与应用创新点

### 技术创新

1. 技能树先选追问目标，模型只改写问题。低分后的练习方向由题库的未覆盖锚点驱动，避免自由生成改变评分口径。
2. 同一套练习数据串联保存、评分依据和复练。主题级改进建议有原轮次证据可追溯，也能生成独立专项练习。
3. 小青以岗位检索、只读 Function Calling、来源证据和站内行动串联一次交互。模型故障时，用户仍能沿本地指引完成准备。
4. 文字与语音共享正式答题和报告路径，实时对话另外保存表达建议。切换模式前保留状态边界。

### 应用创新

1. 把入门练习做成用户可以立刻完成的短任务。题库、指引和示例帮助第一次使用的用户降低配置成本。
2. 横向覆盖技术及非技术岗位，同时支持英语面试。不同方向共享产品流程，题目和学习指南仍按岗位隔离。
3. 报告用在后续准备中。用户能将薄弱点复练为具体行动，也可按范围分享报告和在社区交流经验。

### 验证方式

技术点由源码、集成测试和可复现操作证明。商业收益、学生能力提升和总体内容正确率留待受控试用与独立抽查。

### 本地复现路线

1. 使用 README 的离线启动命令，以空 SQLite 或隔离数据库运行。访问首页、题库和社区验证公开入口。
2. 创建 5 分钟文字练习，提交一个公开合成回答，核对保存确认与追问。完成后查看报告和对应的复练入口。
3. 用独立测试账号验证小青、个人资源访问和社区互动。用浏览器改变窗口宽度，核对提示、焦点与键盘操作。

### 本轮验收边界

### 服务端变量

文本使用 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL。语音使用独立的 DOUBAO_VOICE_API_KEY 和 VOICE 相关开关。远程嵌入、Judge0 和 SMTP 属于可选能力。AUTH_CHALLENGE_SECRET 用于验证码签名。模板只包含配置项与安全示例，评审无需获得服务商密钥。

### 部署验收

检查 /api/health、/api/voice/config、论坛页面及其公开数据接口。登录测试账号完成一次核心流程。公网语音还须使用真实设备从授权、识别到播放逐项验收。启用外部供应商前核对访问、额度和限流。数据库备份与恢复步骤见部署说明。

### 材料提交

使用公开仓库链接和本 PDF。已有 MP4 和在线演示分别填写赛事表单。在线需要登录时，仅通过评审专用提交字段发放独立账号，避免使用个人账号或把凭据写进 README、PDF 或视频。

## 11 总结、展望与源码索引

青栈已实现从准备、作答和评分依据到复练的完整路径。基于题库和技能树可独立验证关键业务规则。配置模型和语音后，可在同一产品架构中扩展交互形态。

1. 质量评测。按岗位构造合成样本并由人工标注锚点，比较规则、模型及检索增强在追问有效性和证据准确性上的差异。
