## 产品与技术

入口为`/assistant`，顶部常驻“小青助手”。“练习概览”放入“更多功能—记录与复盘”，保留4个主要导航，避免移动端挤压。登录使用白名单回跳。

交互参考公开的快捷话题、独立会话与历史管理模式：[腾讯云AI小助手](https://cloud.tencent.com/document/product/1095/103745)、[阿里云会话历史](https://help.aliyun.com/zh/agentrun/session-history)。参考交互思路，视觉沿用青栈；不复制品牌素材或推测内部代码。

业务链路：选择方向 → 快捷问题填入草稿或直接提问 → 选择只读工具 → 检索题目与指南 → 生成建议并展示依据 → 用户主动进入对应方向/时长的练习 → 使用既有报告、任务和笔记继续准备。工具不会自动写计划、修改账户或开始面试。

访客使用明确标注的题库指引演示；登录后使用已配置的智能服务并保存多轮对话。模型关闭或首段失败时显示本地指引，不冒充AI生成。中途断流保留片段和错误，不保存为完整回合。可新建、查看、重命名、删除对话；删除使用白底确认框。

实现位置：

- `frontend/assistant/`：React视图、Hook状态、强类型SSE协议、安全文本展示与错误边界。
- `tools/build_assistant.cjs`、`ui/compiled/`：esbuild编译结果与源码哈希；Python构建会拒绝过期产物。
- `ui/templates/assistant.html`、`ui/styles/97-assistant.css`：公共导航、独立页面样式；首页不加载React。
- `backend/app/api/assistant.py`：认证、账户归属、限流、版本、SSE、完整回合保存和重放。
- `backend/app/services/assistant.py`：工具规划、检索、上下文、生成和明确兜底。
- `data/assistant_guides.json`：六方向自有学习指南，不是标准答案或专业审校结论。

数据升级增加`005_assistant`及`assistant_conversation`表；删除账户时清除对应对话，不更改旧练习数据。每账户最多20个对话、每段20轮、每次输入1200字；模型使用最近8条消息。每回合最多一次工具规划和一次生成，输出上限1000token/6000字；有单回合预算、2路进程内并发与进程内IP限流。多进程部署仍需共享配额和分布式限流，本轮不声称具备公网容量验证。

随机消息标识和版本号防止重复保存；已提交回答可重放，避免重复模型调用。未完成请求使用有期限租约。停止接收或断开连接会进入清理流程；供应商等待受超时限制，不承诺撤销已经发生的计费。保存前重新核对账户凭据。

工具参数严格限制，不能执行任意SQL、外部URL、账户切换或文件操作。对话做基本邮箱、手机号、身份证文本脱敏，不保证识别全部个人信息。模型HTML不执行，模型地址不自动转成链接；参考与行动地址由后端生成，前端再限制为已知站内路径。

## 开发与验收

在frontend运行`npm ci`（首次）、`npm run check:assistant`与`npm run build:assistant`，然后回根目录执行`python tools/project.py build`。已附编译结果，普通同源启动不需要重新下载npm依赖。修改React源码或构建配置后才需先编译助手。

测试入口为`backend/tests/test_assistant.py`、`frontend/tests/assistant-stream.test.ts`、既有前端检查与数据库版本回归。`python evals/assistant_probe.py`默认离线，显式加`--live`才调用配置的模型，输入为公开合成题目，不读取账户数据。

本次真实模型探针成功完成Function Calling和流式生成，返回4项资料、363个增量片段；首个增量约4.89秒，总耗时约16.14秒。这是一次合成输入观测，不是延迟承诺、负载测试或内容质量结论。最终证据位于`docs/logs/2026-11-16/assistant/`，该目录不纳入普通源码分发。

最终回归覆盖94项不同后端用例、43项前端用例，严格TypeScript检查及34组页面检查通过。另验证网络失败用量未知时停止后续调用、模型异常结束不保存成完整回答、流关闭后释放资源。隔离预览使用专用SQLite和合成账户qing_review；真实账户资料未用于模型验收。

实屏已验证登录回跳、历史恢复、连续追问、停止接收及恢复提示、重命名成功提示和390px移动布局。手机上修复了方向标签被挤成竖排的问题。停止接收不会承诺退回已经产生的模型费用。

内容抽查发现模型将联合索引列顺序与WHERE条件顺序混淆；补充[MySQL联合索引文档](https://dev.mysql.com/doc/refman/8.4/en/multiple-column-indexes.html)和[范围优化文档](https://dev.mysql.com/doc/refman/8.4/en/range-optimization.html)整理的依据后，追问纠正了条件顺序，但维护成本仍出现不准确概括。因此继续加强了事实边界提示与学习指南，尚未证明知识回答整体正确。专家审校、逐条事实评测与无检索对照仍为P0验收项，不能以接口测试替代。
